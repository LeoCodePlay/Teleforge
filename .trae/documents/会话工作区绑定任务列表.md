# 历史会话 → 按工作区绑定的任务列表

## Context（背景）

当前「历史会话」面板是平铺的会话列表，会话只按 `connKey`（服务器 / 本地）隔离，工作区是**连接级全局状态**：切换工作区会同时影响所有会话的执行目录，切回旧会话也不会还原它的工作区。

需求（对齐 E:\RJ\DmRJ\deepseek-harness 的侧栏任务列表——工作区分组树）：

1. 「历史会话」改为「任务列表」，记录按**工作区**分组。
2. 每个会话绑定自己的执行工作区：切回某工作区的会话时，自动把当前工作区切到该会话绑定的工作区（远程工作区单独显示「远程任务列表」，本地工作区显示「本地任务列表」）。
3. **会话间工作区隔离**：在新会话里改工作区，不影响旧会话执行时的工作区（后台并行会话各自用自己的工作区）。

## 核心设计

- 会话元数据（`SessionMeta`）增加 `workspace`（远程绑定）与 `localWorkspace`（本地绑定）字段。
- 切换/创建/恢复会话时，把该会话的绑定应用到当前连接（`ssh.workspace` / `localFs.workspace`），UI 自动跟随（`status.workspace` 已由 `emitStatus` 下发）。
- 会话运行期间（`_runTurn`）用新增的 AsyncLocalStorage 作用域隔离工作区：后台并行会话各自读到自己的工作区；**无绑定的旧会话回退到连接级工作区**（作用域传 `undefined`，不能传 `null`，否则旧会话的工具会报「尚未选择工作区」）。
- 新建会话（`session_create`）捕获**当时**的连接工作区作为绑定；`set_workspace` / `set_local_workspace` 只更新当前会话的绑定（前端草稿态传 `sid: null` 不绑定任何会话）。

## 实施步骤

### Phase 1 — 会话存储（server）

**`server/store/session-store.ts`**
- `SessionMeta` 增加可选字段 `workspace?: string | null; localWorkspace?: string | null`（旧 `sessions.json` 行不迁移也合法）。
- `create(title, connKey?, opts: { workspace?, localWorkspace? } = {})`：把绑定写入新行。
- 新增 `setWorkspace(id, ws)` / `setLocalWorkspace(id, lws)`：只改字段并 `writeIndex`，**不动 `updatedAt`**（避免列表重排抖动）。

### Phase 2 — 工作区作用域（server）

**`server/core/ssh-manager.ts`**

**`server/core/local-fs.ts`**

### Phase 3 — Agent 会话绑定（server）

- **`server/api/rpc/agent.ts`**：`session_switch` / `session_create` / `session_fork` / `session_delete` 加 `emitStatus`（切换会话后下发新工作区，这是 UI 自动切换的关键）。

## 边界情况

- 旧会话（无绑定）后台执行回落连接级工作区（`?? undefined`），切换它们不清空当前工作区。
- 同连接两个不同工作区的会话并行：ALS 嵌套作用域各自隔离。
- 草稿（`__new__`）：`sid: null` → 不重绑旧会话；`session_create` 捕获草稿期选好的工作区。
- `forkSession` 继承源会话绑定；删除活跃会话经 `_settleActive` 重新应用绑定。
- 重启恢复：`_restore` 把恢复会话的绑定重新应用回活动连接。
- 环境快照不主动清空：`_buildRuntimeContext` 已有 `env.workspace === ssh.workspace` 比较自愈。

1. `npm run typecheck`（前后端都过）。
2. `npm test`（现有套件保持绿；`session-scope.test.js` 的 `create(title, null)` 向后兼容）。
3. 手动 `npm run dev`：
   - 本地模式：两个本地工作区 → 「本地任务列表」两个分组；切会话本地工作区 chip 与本地文件面板根目录跟随。
   - 连接模式：两个远程工作区的会话分别归入「远程任务列表」对应分组；「本地任务列表」仍可见。
   - 组内「＋」：切工作区 → 进草稿；首条消息落在新工作区，新会话出现在该分组。
   - 并行隔离：在绑定 `/a` 的会话开长任务，切到绑定 `/b` 的会话再开一个，验证各自 `run_command` 的 cwd / `list_directory` 用各自工作区。
   - 旧会话在「未指定工作区」；切换它不清工作区 chip。
   - 重启服务端：恢复会话的工作区重新应用。
