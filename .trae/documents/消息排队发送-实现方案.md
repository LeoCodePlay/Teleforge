# 消息排队发送 — 实现方案

## Context（背景）

当前对话进行中（Agent 工作中）发送消息会立即作为 **steer** 注入下一步，打断当前回复。需求：
- 对话进行中仍可输入，输入框有内容时右下角"暂停按钮"变为"发送按钮"
- 发送后消息**默认进入"待执行队列"**，不打断当前回复
- 队列显示在输入框上方，每条显示"等待执行"，右侧操作栏：**立即执行 / 编辑 / 删除**
- 编辑 = 撤回文本到输入框重新编辑；删除 = 直接从队列移除
- **执行时机**（）：当前 turn 结束后自动按 FIFO 逐条执行（队列由服务端持有，`placement:'queued'` 语义；本项目已具备同款机制的 `rt.inbox` + `_drain` 主循环）

## 核心设计

- 队列由**后端持有**（`rt.pending`），前端渲染快照、发操作 RPC。执行时机 = `_drain` 循环每轮结束后自动把 pending 下一条移入 inbox 续跑（FIFO，一次一条，busy 保持到排空）。
- **停止只停当前轮**：aborted 时 pending 原样保留，下次对话正常结束后队列自动续跑。
- **立即执行**：忙碌时移入 `rt.steer`（注入当前运行下一步，即原 steer 语义）；空闲时直接开新轮。
- **安全边界**（已由 Plan agent 验证）：
  - `_runTurnInner` finally 的 steer→inbox 迁移（aborted 门控）在 `_runTurn` 返回前完成，`_drain` 的 pending 迁移在其后执行，顺序天然正确
  - `submit()` 空闲路径"先排空 pending 再 push 本次输入"单线程不可重入，FIFO 成立
  - 内部提醒 `_toolRepeatReminder` 直接 `unshift` 到 steer（internal），不受影响
  - 队列仅存内存，服务重启后清空（已知限制）；`clearHistory` 忙时抛错、idle 时 pending 必空

## 改动清单

### 1. 后端 `server/agent/agent.ts`
- `newRuntime()`：新增 `pending: []`（元素 `{id, text, reasoning}`）、`queueSeq: 0`
- 新增 `_emitQueue(rt, sid)`：`emit('agent', {event:'queue_update', queue: pending.map(p=>({id, text})), sid})`
- 新增 `queueSnapshot(id)`：返回 pending 快照
- `submit()`：忙碌 → `pending.push({id:++queueSeq, text, reasoning})` + `_emitQueue`（**去掉**原 `steer.push` + steer 事件）；空闲 → 先 `while(pending.length) inbox.push(pending.shift())` + `_emitQueue`，再 push 本次输入 + `_drive`
- 新增 `steerQueueItem(id)`（立即执行）：从 pending 移除 → 忙碌时 `steer.push` + emit `steer` 事件；空闲时 `inbox.push` + `_drive`；随后 `_emitQueue`，返回最新快照
- 新增 `removeQueueItem(id)`：splice 移除 + `_emitQueue`，返回最新快照
- `_drain()`：循环体改为 `const endReason = await this._runTurn(...)`；`endReason?.kind !== 'aborted'` 且 pending 非空时移下一条进 inbox + `_emitQueue`；finally 不变
- `_runTurnInner()`：函数末尾 `return endReason`（L707 已声明该变量）

### 2. 后端 `server/api/rpc/agent.ts`
- `get_history`：reply 增加 `queue: agent.queueSnapshot(agent.sessionId)`
- 新增 `queue_steer`：`reply({type:'ok', ...agent.steerQueueItem(msg.id)})`
- 新增 `queue_remove`：`reply({type:'ok', ...agent.removeQueueItem(msg.id)})`

### 3. 前端 `web/src/components/QueuePanel.tsx`（新建）

## 验证方法
- 启动：`npm run dev:server` + `npm run dev:web`（或 `npm run dev`），类型检查 `npm run typecheck`
- 手动用例：
  1. 空闲发送 → 立即执行不进队列
  2. 长任务工作中连发多条 → 队列逐条出现"等待执行"，不打断流式输出；有输入显示 ➤、空输入显示 ⏹
  3. 当前轮结束后 → 队列第一条自动执行，FIFO 逐条到排空
  4. 忙碌时"立即执行" → 该条作为 steer 消息进入对话流并在下一步被响应
  5. 编辑 → 撤回输入框、焦点就位、从队列移除；删除 → 确认框后移除
  6. 停止 → 只停当前轮，队列项保留；再发送 → 队列先执行
  7. askPending 挂起 → 输入禁用、按钮为 disabled ➤、不出 ⏹
  8. 会话切换 → 队列随会话复位，后台会话 queue_update 不串
